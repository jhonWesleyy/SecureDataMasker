# Masking policy

> **Status: Phase 2 specification.** This document fixes the masking output that Phase 4 will
> implement and test. No masking code exists yet.

This document is the contract for `MaskingPreset` and `MaskingPolicy`
(`io.github.jhonwesleyy.securedatamasker.core.masking`). It applies to free text
(`TextMasker.mask`), to known values (`TextMasker.maskValue`) and to the `toString()` of the value
types (`Cpf`, `Cnpj`, `Email`, `PhoneNumber`, `PixKey`), which always use `BALANCED`.

Every example uses fictitious data only. The CPF and the numeric CNPJ were generated by the
check-digit algorithm; `12.ABC.345/01DE-35` is the public example from the Receita Federal; e-mail
domains are reserved by RFC 2606; the phone numbers are synthetic.

## 1. Rules that apply to every type

1. **Fixed length.** The number of mask characters never depends on the length of the hidden
   value. Fixed-length types (CPF, CNPJ, EVP) keep their canonical length. Variable-length segments,
   such as the e-mail local part and domain, are replaced by exactly `fixedMaskLength` mask
   characters (default 3). Landline and mobile numbers are masked to the same shape.
2. **Nothing is revealed from a short variable-length segment.** For the e-mail local part (the
   only variable-length segment that a preset reveals from), characters are revealed only when
   strictly more stay hidden than are revealed: a local part of length `n` reveals `p` leading
   plus `s` trailing characters only if `n ≥ 2 × (p + s) + 1`. Otherwise it is fully masked. For
   example `ab@example.com` under `BALANCED` gives `***@example.com`, not `a***@example.com`.
   Fixed-length types (CPF, CNPJ, phone, EVP) reveal exactly what their table says.
3. **Formatting.** With `preservesFormatting() == true` (the default in all presets), separators
   in the input (`.`, `-`, `/`, spaces, parentheses) stay where they were for CPF, CNPJ and EVP.
   Phone numbers are always written in the canonical masked shape (see section 2.4), because their
   input formats vary too much to keep. With `false`, separators are dropped.
4. **Mask character.** Default `*`. Letters, digits, line terminators and the type separators are
   rejected as mask characters, so masking can never create a new candidate or a new log line
   (threat T13).
5. **Idempotence.** `mask(mask(x)) == mask(x)`. Masked output is never detected again.
6. **Fail-closed (ADR-003).** If masking fails, `TextMasker.mask` returns `[MASKING_FAILED]` in place
   of the whole text. If the text is longer than `maxScanLength`, it returns
   `[MASKING_SKIPPED_INPUT_TOO_LONG]` in place of the whole text. `maskValue` returns
   `[MASKING_FAILED]` when the value is not recognized as the given type.
7. **Letter case is preserved** in revealed characters. Masking never normalizes the text it
   leaves in clear.

## 2. Per-type tables

The `BALANCED` column is the default (D5).

### 2.1 CPF

| Input (fictitious) | `STRICT` | `BALANCED` (default) | `PARTIAL_REVEAL` |
| --- | --- | --- | --- |
| `123.456.789-09` | `***.***.***-**` | `***.***.***-**` | `***.***.***-09` |
| `12345678909` | `***********` | `***********` | `*********09` |

`BALANCED` hides the CPF completely on purpose. The only digits worth revealing would be the
check digits, which help little with debugging and say something about the other nine. Correlation
across events is the job of HMAC pseudonymization (RF16, future).

### 2.2 CNPJ (numeric and alphanumeric)

| Input (fictitious) | `STRICT` | `BALANCED` (default) | `PARTIAL_REVEAL` |
| --- | --- | --- | --- |
| `12.ABC.345/01DE-35` | `**.***.***/****-**` | `**.***.***/****-**` | `12.***.***/****-35` |
| `12ABC34501DE35` | `**************` | `**************` | `12**********35` |
| `11.222.333/0001-81` | `**.***.***/****-**` | `**.***.***/****-**` | `11.***.***/****-81` |
| `12abc34501de35` (lower case) | `**************` | `**************` | `12**********35` |

Letters are masked exactly like digits, so the output does not reveal whether a CNPJ is
alphanumeric.

### 2.3 E-mail

| Input (fictitious) | `STRICT` | `BALANCED` (default) | `PARTIAL_REVEAL` |
| --- | --- | --- | --- |
| `usuario@example.com` | `***@***` | `u***@example.com` | `u***o@example.com` |
| `ab@example.org` | `***@***` | `***@example.org` | `***@example.org` |
| `customer.support@sub.example.com` | `***@***` | `c***@sub.example.com` | `c***t@sub.example.com` |

- `STRICT` hides the domain as well; the `@` stays, so the reader still knows an address was there.
- `BALANCED` and `PARTIAL_REVEAL` keep the domain (`keepDomain()`). A domain can still identify a
  small organization: if that matters, use `STRICT` for `EMAIL`.
- The three stars are fixed: `u***@example.com` could come from a local part of 3 or of 30
  characters. A local part shorter than 3 characters reveals nothing (section 1, rule 2), which is
  why `ab@example.org` is fully masked.

### 2.4 Phone

The output always has the shape `(**) *****-NNNN`, with nine subscriber positions, whatever the
input format and whether the number is a landline (8 digits) or a mobile (9 digits). When the input
starts with `+55`, the output starts with `+55 `. The country code is not sensitive, and keeping it
tells the reader the original format.

| Input (fictitious) | `STRICT` | `BALANCED` (default) | `PARTIAL_REVEAL` |
| --- | --- | --- | --- |
| `(11) 91234-5678` | `(**) *****-****` | `(**) *****-5678` | `(11) *****-5678` |
| `(11) 3123-4567` (landline) | `(**) *****-****` | `(**) *****-4567` | `(11) *****-4567` |
| `+55 11 91234-5678` | `+55 (**) *****-****` | `+55 (**) *****-5678` | `+55 (11) *****-5678` |
| `+5511912345678` | `+55 (**) *****-****` | `+55 (**) *****-5678` | `+55 (11) *****-5678` |

Under the default detection mode (D4), a bare run of digits such as `11912345678` is never detected
as a phone (`DetectionMode.SHAPE_OR_VALIDATED`). If it is a valid CPF it is masked as a CPF, which
is the CPF/phone ambiguity described in spec section 1.2. `maskValue(PHONE, "11912345678")` still
masks it as a phone, because the caller has stated the type.

### 2.5 Pix random key (EVP)

| Input (fictitious) | `STRICT` | `BALANCED` (default) | `PARTIAL_REVEAL` |
| --- | --- | --- | --- |
| `123e4567-e89b-12d3-a456-426655440000` | `********-****-****-****-************` | `********-****-****-****-********0000` | `********-****-****-****-********0000` |

`PARTIAL_REVEAL` is the same as `BALANCED`. An EVP is random, so revealing more of it does not
help debugging any more than the last four characters do.

### 2.6 Other Pix keys

A Pix key of type CPF, CNPJ, e-mail or phone is masked with the policy of its underlying type.
In the DICT form, a phone key is always E.164 (`+5511912345678` → `+55 (**) *****-5678`) and a CPF
or CNPJ key has no punctuation (`12345678909` → `***********`).

## 3. Preset definitions as policies

This is how each preset maps to `MaskingPolicy` settings. Every preset keeps formatting and uses
`*` and a fixed mask length of 3.

| Type | `STRICT` | `BALANCED` | `PARTIAL_REVEAL` |
| --- | --- | --- | --- |
| CPF | `fullyMasked()` | `fullyMasked()` | `revealLast(2)` |
| CNPJ | `fullyMasked()` | `fullyMasked()` | `revealFirst(2).withRevealedSuffix(2)` |
| EMAIL | `fullyMasked()` | `revealFirst(1).keepDomain()` | `revealFirst(1).withRevealedSuffix(1).keepDomain()` |
| PHONE | `fullyMasked()` | `revealLast(4)` | `revealFirst(2).withRevealedSuffix(4)` (area code + last 4) |
| PIX_EVP | `fullyMasked()` | `revealLast(4)` | `revealLast(4)` |

For e-mail, prefix and suffix refer to the local part, and section 1, rule 2 applies. For phone,
the prefix is the area code and the suffix is the end of the subscriber number. The last four
digits are revealed for landlines too: the masked shape has nine subscriber positions either way,
so the output does not say which kind of number it was.

## 4. What the policy does not promise

- **Partially revealed data may still be personal data** under the LGPD. `PARTIAL_REVEAL` is meant
  for environments where that is acceptable, not as an anonymization method.
- Masking hides values the scanner detects. Values in obfuscated or non-ASCII formats (spec
  section 5, threat T8) are not detected, so they are not masked either.
