# ADR-005: One CNPJ algorithm, alphanumeric

- **Status:** Accepted
- **Date:** 2026-11-05
- **Phase:** 2 (Architecture)

## Context

The Receita Federal introduced the alphanumeric CNPJ, and the first ones were issued in July 2026
(spec, Sources). Its 12 base positions are `[0-9A-Z]`, followed by 2 numeric check digits. Each
character is valued as its ASCII code minus 48, and the check digits use mod 11 with weights 2 to
9. Existing numeric CNPJs remain valid.

## Decision

- Implement **one** algorithm, the alphanumeric one, for every CNPJ. It is backward compatible:
  for `'0'..'9'`, ASCII − 48 is the digit itself, so a numeric CNPJ is the special case where every
  base position is a digit.
- Accept lower-case letters and normalize them to upper case with `Locale.ROOT` (RF06).
- The check digits must be ASCII digits. Letters are only accepted in the 12 base positions.
- `Cnpj.isAlphanumeric()` reports whether any base position is a letter. Masking does not reveal
  this (`docs/masking-policy.md`, section 2.2).
- Detection of unformatted alphanumeric candidates requires a valid check digit in the default
  mode (D4). Without it, hashes and order IDs would cause too many false positives (spec section 1.2).

Fixed reference values come only from the public Receita Federal example (`12.ABC.345/01DE-35`)
and from values generated by the algorithm (for example `11.222.333/0001-81`).

## Consequences

- One code path and one test suite. Numeric CNPJs are covered by the same property tests.
- A validator that accepted digits only would have been outdated from day one.
- The validator accepts the full `[A-Z]` range for the base positions, as described in the
  official Q&A. If the Receita publishes a narrower alphabet, that is a validation change recorded
  in the CHANGELOG.

## Alternatives considered

| Alternative | Why rejected |
| --- | --- |
| Two validators (numeric and alphanumeric) | Duplicates the algorithm; the numeric one is a special case |
| Numeric only, alphanumeric "later" | Already in production since July 2026; would ship outdated |
| A flag to reject alphanumeric CNPJs | No requirement asks for it; a caller who needs it can check `isAlphanumeric()` |
